# vysh — концепция и архитектура

> Документ — источник правды для архитектурных решений; обновляется вместе с кодом. Актуальный список пользовательских возможностей — в [README.md](../README.md).
>
> **В планах (ещё не реализовано):** порт `TerminalEngine` (терминал использует `xterm2` из `third_party/xterm2`), локальное хранилище секретов с мастер-паролем (сейчас секреты хранятся в системном keyring, а шифрование паролем доступно при экспорте резервной копии), `ssh-agent` / Pageant (режим `agent` пока перебирает стандартные ключи из `~/.ssh`), импорт `~/.ssh/config`, докачка SFTP по смещению, палитра команд `Ctrl+K`, поиск в терминале, AppImage / .deb / AUR / установщик Windows.

## Надёжность: принятые правила

- **Файлы конфигурации** (`JsonStore`) пишутся через временный файл и атомарный `rename` поверх старого; прежняя версия остаётся в `.bak`, битый файл перед перезаписью откладывается в `.corrupt-<время>`. Ошибка записи показывается пользователю.
- **Один экземпляр на профиль.** Пока vysh запущен, главный процесс держит блокировку `vysh.lock`; второй запуск с тем же профилем сообщает об этом и ничего не перезаписывает.
- **Загрузка по SFTP** идёт во временный `.имя.vysh-*.part` рядом с целью и заменяет файл только после успеха (posix-rename, либо старый файл отодвигается и возвращается при сбое). Симлинки не заменяются.
- **Скачивание** идёт в `имя.vysh-part`, путь резервируется на время передачи; имена с сервера очищаются (`LocalFiles.safeName`) и не могут выйти за папку загрузки.
- **Сессия** нумерует попытки подключения: всё, что пришло от прежней попытки (поздний shell, `done` старого транспорта, SFTP-канал), освобождается и не трогает новую. Закрытие вкладки прерывает попытку сразу.
- **Пароль в памяти** сессии привязан к цели `user@host:port` и способу входа; смена цели его сбрасывает. Сохранённый пароль при смене адреса, порта или пользователя в редакторе удаляется, а не уходит на новый сервер.
- **Системные программы** запускаются без разбора строки shell'ом (на Windows не через `cmd`). Файлы с сервера, которые Windows запустила бы (`.bat`, `.exe`, `.ps1` и т.п.), открываются в Блокноте.

## 0. Что это

**vysh** — SSH-менеджер подключений без подписок, аккаунтов и лишних функций.

Принципы:
- **Минимум функций, максимум удобства.** Только то, что нужно для ежедневной работы с серверами.
- **Выразительный интерфейс.** Material 3 Expressive / Material You, пружинная физика отклика, плавные переходы и темы.
- **Везде одинаково хорошо.** Windows 10/11, Linux (от Arch с Hyprland до классических окружений), macOS 12+ и Android 8+.
- **Уважает систему.** Окно ведёт себя как обычное приложение в любом оконном менеджере; цвета подхватываются из системы и конфигураций окружения и обновляются на лету; системное отключение анимаций соблюдается.
- **Локально и бесплатно.** Без облака и телеметрии. Лицензия GPL-3.0-or-later.

## 1. Функциональность

### 1.1 Реализовано
| Блок | Что входит |
|---|---|
| **Главная (Hosts)** | Карточки хостов: имя, `user@host:port`, сворачиваемые группы на сливерах, цветные метки, поиск, индикатор доступности (TCP-ping), массовые действия |
| **Редактор хоста** | Боковая панель (side sheet): адрес, порт, логин, пароль / ключ / автоподбор, группа, цвет, KeepAlive, «Сохранить и подключиться» |
| **Быстрое подключение** | `user@host:port` в поле поиска и Enter |
| **Вкладки и окна** | Вкладки сессий с перетаскиванием, дублированием и индикацией статуса; split-панели (по горизонтали и вертикали); вынесение вкладок в автономные системные окна (включая Wayland) и перенос между окнами без разрыва сессии |
| **Терминал** | 256 цветов / truecolor, мышь, выделение и копирование (три режима, включая свои сочетания), scrollback, нагрузка сервера в строке состояния; локальная сессия через `flutter_pty`; выбор системного или своего шрифта и межстрочного интервала; экранная панель клавиш с автоповтором на Android |
| **Файлы и SFTP** | Одиночная панель у вкладки со слежением за текущей папкой терминала (OSC 7/1337/9;9 и `/proc`), двухпанельная рабочая область с побайтовой сверкой при копировании, drag&drop в обе стороны, очередь передач с прогрессом/скоростью/отменой, `mkdir` / `rename` / `delete` / `chmod`, редактирование удалённого файла локальным редактором |
| **Диагностика** | Экран ошибки с причиной и журналом, ping, трассировка, проверка порта |
| **Безопасность и бэкап** | Проверка ключа сервера (`known_hosts`, предупреждение при смене), пароли в системном хранилище, подтверждение многострочной вставки, зашифрованный экспорт/импорт профиля в фоновом изоляте |
| **Обновления** | Проверка релизов GitHub, сверка SHA-256, автозамена и перезапуск для portable-сборок Windows и Linux, системный установщик APK на Android |

### 1.2 Дальнейшие планы
1. Сниппеты — сохранённые команды с отправкой во вкладку
2. Проброс портов (`L` / `R` / `SOCKS`) и Jump host (`ProxyJump`)
3. Импорт `~/.ssh/config`, палитра команд `Ctrl+K`, поиск по буферу терминала
4. `ssh-agent` / Pageant и локальный vault-файл секретов с мастер-паролем
5. Broadcast ввода в несколько вкладок и режим хоста «через системный `ssh`» (Kerberos, FIDO2, `ProxyCommand`)

### 1.3 Не делаем
Аккаунты, собственное облако, командная работа, подписки, телеметрия, комбайн несвязанных протоколов (RDP, VNC, Telnet и т.п.).

**Изоляция слоёв.** SSH скрыт за портами `SshTransport` и `SftpSession`, локальная оболочка — за `LocalShellLauncher` и `TerminalShell`. При необходимости транспорт можно заменить без переписывания UI.

```
┌─────────────────────────── ui (Flutter, M3 Expressive) ───────────────────┐

│ SessionView · SftpPane · FileWorkspace · SettingsPage · ui/motion/*       │
└───────────────▲───────────────────────────────────────────────────────────┘
                │ Riverpod providers
┌───────────────┴──────────────────── app ─────────────────────────────────┐
│ HostsController · TabsController · SettingsController · TransferQueue     │
│ ExternalColors · UserFonts · UpdateController · Backup · DetachedWindows  │
│ TerminalSession · CurrentDirectory · SftpActions · FileCopy               │
└───────────────▲───────────────────────────────────────────────────────────┘
                │
┌───────────────┴──────────────────── domain ──────────────────────────────┐
│ Модели: Host, SessionTab, ExternalColors, Catppuccin                     │
│ Сервисы: known_hosts, нагрузка сервера, разбор шрифтов                   │
│ Порты: SshTransport · SftpSession · TerminalShell · SecretStore · …      │
└───────────────▲───────────────────────────────────────────────────────────┘
                │ реализации
┌───────────────┴─────────────────── infra ────────────────────────────────┐
│ ssh/       dartssh2 → SshTransport, SftpSession                          │
│ local/     flutter_pty (и резервный script на Unix) → TerminalShell      │
│ secrets/   KeyringSecretStore                                            │
│ storage/   атомарный JsonStore в папке профиля, AppPaths                 │
│ update/    UpdateService, UpdateInstaller (SHA-256, PowerShell/tar/APK)  │
│ platform/  окно, источники цветов, шрифты, локальные файлы, диагностика  │
└───────────────────────────────────────────────────────────────────────────┘
```

Правило зависимостей: **`ui → app → domain ← infra`**. Слой `domain` импортирует только `dart:` и собственные файлы; `infra` не зависит от `app`, `ui` и `l10n`; `app` не импортирует `ui`. Тест `test/architecture_test.dart` проверяет эти инварианты автоматически.

### 3.1 Основные сущности
- **Host** — `id`, `label`, `address`, `port`, `username`, `auth` (`password | key | agent`), `keyPath`, `group`, `color`, `keepAliveSeconds`, `lastConnectedAt`. Пароли хранятся отдельно в `SecretStore` по `id` хоста.
- **Session** — живое соединение (`TerminalSession`): `Host` + `SshTransport` или `LocalShellLauncher`, статус (`connecting / ready / lost / closed`), отслеживание текущего каталога и ленивый SFTP-канал поверх того же соединения.
- **Tab** — вкладка `SessionTab`: терминал, прикрепляемая SFTP-панель и участие в split-компоновке окна.
- **Transfer** — задача в `TransferQueue`: направление, пути, размер, прогресс, скорость и отмена.

### 3.2 Хранение данных
- Windows: `%APPDATA%\vysh\`; Linux: `$XDG_CONFIG_HOME/vysh/` (обычно `~/.config/vysh/`); macOS: `~/Library/Application Support/vysh/`; Android: внутреннее хранилище приложения. На ПК путь переопределяется через `VYSH_CONFIG_DIR`.
- Файлы профиля (`hosts.json`, `settings.json`, `known_hosts.json`, `colors.json`, `fonts/`) не содержат открытых секретов и подходят для синхронизации через git или Syncthing.

## 4. Внешний вид, система движения и темы

### 4.1 Дизайн и система движения (`lib/ui/motion/`)
- **Material 3 Expressive:** компактная верхняя полоса вкладок, скруглённые панели, боковая шторка редактора хоста, сегментированные переключатели `ExpressiveSegments` со скруглением активного сегмента в пилюлю.
- **Разделение пружин:** пространственные пружины (`AppMotion.spatialFast`, `spatialDefault`, `spatialSlow`, `fold`) допускают лёгкий естественный перелёт для размеров, скруглений и перемещений; пружины эффектов (`effectsFast`, `effectsDefault`, `effectsSlow`) критически затухают ($\zeta = 1$) без перелёта для цвета и прозрачности.
- **Тактильные поверхности (`PressableSurface`):** отслеживание касания через `Listener` без конкуренции с жестами прокрутки и перетаскивания, сжатие и морфинг радиуса углов при нажатии.
- **Без лишних перестроений:**
  - `LayeredSwitcher` удерживает разделы и панели в дереве со своими позициями прокрутки и отключает тикеры скрытых вкладок;
  - `ExpandSection` монтирует раскрываемый блок в первом же кадре, а в открытом покое убирает обёртки обрезки; во время выезда SFTP-панели и возврата split-разделителя `autoResize` у PTY приостанавливается до завершения пружины;
  - `SliverReveal` сворачивает группы карточек на уровне `RenderProxySliver`, не создавая виджеты за пределами вьюпорта;
  - `SmoothScrollController` экспоненциально сглаживает дискретные щелчки колеса мыши на ПК, оставляя нативную сенсорную инерцию на Android и тачпадах;
  - `ThemeTransitionHost` снимает кадр `RenderRepaintBoundary` перед сменой темы или акцента и раскрывает обновлённый интерфейс круговой маской от точки нажатия, перестраивая открытые терминалы ровно один раз.
- **Энергосбережение и доступность:** бесконечные индикаторы останавливаются в скрытых вкладках и при свёрнутом приложении (`AppMotion.onScreen`), а системный режим уменьшения движения (`MediaQuery.disableAnimations`) мгновенно переключает состояния.

### 4.2 Источники цвета
Все источники приводятся к единой модели (`ColorScheme` + 16-цветная палитра терминала) и применяются на лету. Подробное руководство — в [THEMES.md](THEMES.md).

1. **Встроенные акценты** — 9 пресетов на ПК и системная палитра Monet на Android.
2. **Catppuccin** — Latte, Frappé, Macchiato, Mocha и 14 акцентов.
3. **Акцент системы** — реестр Windows или `xdg-desktop-portal` (`org.freedesktop.appearance`) на Linux с подпиской по D-Bus.
4. **Файлы окружения (Linux)** — автоматическое слежение за `colors.json` профиля (шаблоны для matugen и wallust в `themes/templates/`), `caelestia` и `pywal`.

### 4.3 Шрифты терминала
1. **Системные моноширинные:** разбор таблиц `cmap` и `hmtx` в TTF/OTF/TTC (`domain/services/font_info.dart`) в фоновом изоляте отбирает реальные моноширинные шрифты (включая Nerd Font без `Mono` в названии и CJK с полуширинной латиницей).
2. **Пользовательские файлы:** импорт `.ttf` / `.otf` до 32 МБ в `fonts/` профиля через `FontLoader` на всех платформах, включая Android.
3. **Встроенный шрифт:** на Windows и Linux используется Cascadia Mono с цепочкой фолбэков; на macOS и Android по умолчанию задействуется **JetBrains Mono NL** из ассетов сборки. Лигатуры в терминале всегда отключены.

## 5. Окна и оконные менеджеры

- `app_id` / `WM_CLASS` = `dev.vysh.vysh` для правил Hyprland, sway, i3 и других WM.
- Режимы заголовка (`auto | system | custom`): `custom` встраивает полосу вкладок в заголовок окна (со snap layouts в Windows и отступом под светофор в macOS); в тайлинговых WM (`Hyprland`, `sway`, `i3`, `niri`, `river`) режим `auto` выбирает `system` без лишних декораций.
- Нативный Wayland с резервным X11; геометрия окна сохраняется между запусками (на Wayland позиционирование остаётся за композитором).

### Автономные окна сессий (`lib/app/windows/`)
- Каждое вынесение вкладки создаёт полноценное системное окно со своим `AppShell`, полосой вкладок, split-областью, настройками и проводником SFTP.
- **Браузерная модель жизни окон:** закрытие изначального окна скрывает его, не затрагивая вынесенные окна; закрытие вынесенного окна завершает только принадлежащие ему вкладки; перенос последней вкладки в другое окно автоматически закрывает опустевшее окно.
- **Единый владелец сессий:** главный экземпляр остаётся единственным владельцем профиля, SSH/PTY и исходных `Terminal`. Вторичные окна работают через `WindowClient`, `WindowTerminal` и `WindowSftpSession`, получая снимки состояния и кадры ячеек через `TerminalMirrorEncoder` (с синхронизацией `resizeSeq`, прокрутки, выделения и режимов клавиатуры).
- **Транспорт по платформам:**
  - В Windows и macOS вторичные окна создаются как отдельные Flutter-движки внутри процесса (`desktop_multi_window` + стабилизированные FFI-идентификаторы изолятов в `third_party/irondash_message_channel`).
  - В Linux (обход повреждения общего GLX/EGL-контекста при закрытии второго движка во Flutter 3.47) каждое окно запускается отдельным процессом и общается с владельцем по постоянному бинарному Unix-сокету (`StandardMessageCodec`) с событийной push-доставкой кадров без поллинга.
- Вытаскивание вкладки за пределы окна (`TabDrag`) работает на Windows, macOS, X11 и Wayland, а наведение на другое окно открывает маркер вставки в полосе вкладок и зоны кросс-оконного разделения.

## 6. CI и структура репозитория

### 6.1 Проверки CI (`.github/workflows/`)
- На каждый push в `main` и PR: `flutter pub get`, `flutter analyze --no-fatal-infos`, `flutter test`, тесты `third_party/irondash_message_channel/test` и проверка целостности патча `tools/xterm2/verify.sh`.
- По тегу `vX.Y.Z`: сверка версий (`pubspec.yaml`, `lib/app/version.dart`, `CHANGELOG.md`) и параллельная сборка Windows ZIP, Linux `tar.gz` + `PKGBUILD`, macOS DMG, подписанных Android APK (`arm64-v8a`, `armeabi-v7a`, `x86_64`) и манифеста `SHA256SUMS`. Подробности — в [RELEASING.md](RELEASING.md).
