# vysh - концепция и архитектура

> Статус: согласовано, версия 1 (2026-10-01). Документ - источник правды для решений; меняем его вместе с кодом.

## 0. Что это

**vysh** - SSH-менеджер подключений «как Termius, но без платного и лишнего».

Принципы:
- **Минимум функций, максимум удобства.** Только то, что нужно для ежедневной работы с серверами.
- **Красиво.** Material 3 / Material You, плавные анимации, темы.
- **Везде одинаково хорошо.** Windows 10/11 и любой Linux - от Arch с Hyprland до Astra.
- **Уважает систему.** Окно ведёт себя как обычное приложение в любом оконном менеджере; цвета подхватываются из системных дотов и меняются вместе с обоями.
- **Локально и бесплатно.** Без аккаунтов, облака, подписок и телеметрии.

## 1. Функциональность

### 1.1 MVP
| Блок | Что входит |
|---|---|
| **Главная (Hosts)** | Сетка/список карточек хостов: имя, `user@host:port`, иконка ОС, группы, теги, поиск, индикатор доступности (TCP-ping) |
| **Редактор хоста** | Боковая панель (side sheet): адрес, порт, логин, пароль / ключ / агент, группа, цвет, иконка, команда при старте. Кнопка «Подключиться без сохранения» |
| **Быстрое подключение** | `user@host:port` в палитре команд |
| **Вкладки** | Каждая сессия - вкладка; Hosts - закреплённая первая. Переименование, перетаскивание, дублирование, переподключение, индикатор состояния |
| **Терминал** | 256 цветов / truecolor, мышь, выделение и копирование, поиск по буферу, свой шрифт (Nerd Font в комплекте), scrollback |
| **SFTP** | Панель файлов у вкладки (локально ⇄ сервер), drag&drop из проводника/файлового менеджера и обратно, очередь передач с прогрессом/скоростью/отменой, докачка, mkdir / rename / delete / chmod, «открыть в локальном редакторе → залить при сохранении» |
| **Безопасность** | Проверка ключа сервера (known_hosts, диалог при первом подключении и при смене ключа), пароли только в защищённом хранилище |
| **Настройки и темы** | См. раздел 4 |
| **Импорт** | Из `~/.ssh/config` |

### 1.2 Потом (по приоритету)
1. Сниппеты - сохранённые команды, отправка во вкладку
2. Проброс портов (L / R / SOCKS)
3. Jump host / ProxyJump
4. Split-панели внутри вкладки
5. Синхронизация без своего облака - экспорт/импорт зашифрованного файла (Syncthing, git, Nextcloud)
6. Broadcast ввода в несколько вкладок
7. SFTP «следует за текущей папкой терминала» (OSC 7)
8. Режим хоста «через системный ssh» - для Kerberos, FIDO2, ProxyCommand

### 1.3 Не делаем
Аккаунты, своё облако, командная работа, подписки, телеметрия, «комбайн всех протоколов» (RDP, VNC, Telnet и т.п.).

## 2. Стек

| Слой | Выбор | Почему |
|---|---|---|
| UI | **Flutter** (Dart), Material 3 | Material You из коробки, один код на Windows и Linux, Wayland через GTK |
| Состояние | **Riverpod** | Простое DI и реактивность без магии |
| SSH + SFTP | **`dartssh2`** | Чистый Dart, живой (4.1.x, 2026), есть SFTP, проброс портов, ed25519/RSA/ECDSA, ChaCha20/AES-GCM. Без нативной сборки |
| Терминал | **`xterm2`** | Поддерживаемый форк `xterm.dart` (оригинал заброшен с 2024) |
| Окно | `window_manager` (+ `flutter_acrylic` для Mica на Windows) | Управление декорациями, размером, прозрачностью |
| Секреты | `flutter_secure_storage` (libsecret / Windows Credential Manager) + свой vault-файл | См. 3.5 |
| Drag&drop | `desktop_drop` | Файлы из ОС в окно |

**Почему не Rust.** Огромные файлы и особое шифрование не нужны, поэтому скорость нативного ядра не окупает усложнения сборки. Прецедент: ServerBox (Flutter + dartssh2 + xterm, вкладки и SFTP на Linux/Windows).

**Запасной план.** SSH и терминал спрятаны за интерфейсами `SshTransport` и `TerminalEngine`. Если `xterm2` не справится, меняем терминал на `flutter_alacritty` (ядро Alacritty на Rust), если `dartssh2` - на `russh`. UI при этом не трогаем.

### Отвергнутые варианты
- **Tauri + xterm.js** - WebKitGTK на старых дистрибутивах (Astra) болезненный.
- **Qt/QML** - Material 3 рисовать руками, терминальный виджет под Windows сложно.
- **Electron** - тяжёлый, на Astra риск.
- **Системный OpenSSH как основа** - пароли, ключи сервера и состояние пришлось бы выковыривать из текста.

## 3. Архитектура

```
┌──────────────────────────── UI (Flutter, M3) ─────────────────────────────┐
│ AppShell: NavigationRail · TabStrip (в заголовке или под ним) · Palette   │
│ Pages: HostsPage · TerminalPane · SftpPane · SettingsPage · HostEditor    │
└───────────────▲───────────────────────────────────────────────────────────┘
                │ Riverpod providers
┌───────────────┴──────────────────── Domain ──────────────────────────────┐
│ HostRepository   SessionManager   TabsController   TransferQueue         │
│ ThemeService     SettingsService  KnownHostsService                      │
│ Интерфейсы: SshTransport · SftpClient · TerminalEngine · SecretStore     │
└───────────────▲───────────────────────────────────────────────────────────┘
                │ реализации
┌───────────────┴─────────────────── Infrastructure ───────────────────────┐
│ ssh/       dartssh2 → SshTransport, SftpClient                           │
│ terminal/  xterm2   → TerminalEngine                                     │
│ secrets/   KeyringSecretStore · VaultSecretStore                         │
│ storage/   JSON-файлы в папке конфигурации                               │
│ platform/  WindowAdapter · ThemeSources (portal, файлы дотов, Windows)   │
└───────────────────────────────────────────────────────────────────────────┘
```

Правило зависимостей: **UI → Domain ← Infrastructure.** Domain не знает ни про Flutter-виджеты, ни про конкретные библиотеки.

### 3.1 Сущности
- **Host** - id, label, address, port, username, auth (password | key | agent), keyRef, secretRef, groupId, tags, color, icon, startupCommand, lastConnectedAt.
- **Group** - id, name, order (один уровень вложенности).
- **Session** - живое соединение: Host + SshTransport + состояние (`connecting / ready / lost / closed`) + keepalive + автопереподключение.
- **Tab** - UI-обёртка над Session: терминал + опциональная SFTP-панель (позже - дерево split-панелей).
- **Transfer** - задача SFTP: направление, пути, размер, прогресс, скорость, статус.
- **Theme** - M3-токены + 16-цветная палитра терминала + источник.

### 3.2 Жизненный цикл подключения
1. Клик по карточке → `SessionManager.open(host)` → новая вкладка в `connecting`.
2. Проверка ключа сервера: новый → диалог «доверять?»; изменился → предупреждение.
3. Аутентификация: пароль из SecretStore / ключ / агент. Ошибка → диалог ввода с галкой «сохранить».
4. PTY `xterm-256color`, размер следует за размером вкладки → `ready`.
5. Обрыв → `lost`, баннер «Переподключить» (Enter).
6. SFTP открывается по требованию поверх **того же** соединения (отдельный канал), повторный логин не нужен.

### 3.3 SFTP
- `TransferQueue` в Domain: параллельно 2-3 передачи, остальные ждут.
- Докачка по смещению, если файл на приёмнике частично есть.
- «Открыть локально»: скачиваем во временную папку, открываем системным редактором, следим за изменением → заливаем обратно.

### 3.4 Хранение
- Linux: `$XDG_CONFIG_HOME/vysh/` (обычно `~/.config/vysh/`); Windows: `%APPDATA%\vysh\`.
- Файлы: `hosts.json`, `settings.json`, `known_hosts`, `themes/`.
- Человекочитаемо и **без секретов** - можно класть в git или Syncthing.
- Данные всегда в профиле пользователя, независимо от того, откуда запущен exe: обновление = удалить старую папку и распаковать новую.

### 3.5 Секреты
- По умолчанию - системное хранилище (Secret Service на Linux, Credential Manager на Windows).
- Если его нет (голый Hyprland без keyring, закрытая Astra) - **vault-файл** с мастер-паролем (Argon2id → XChaCha20-Poly1305), разблокировка при старте, автоблокировка по таймеру.
- Ключи: ссылкой на файл в `~/.ssh` или импортом в хранилище. ssh-agent (OpenSSH agent, Pageant).

## 4. Внешний вид и темы

### 4.1 Дизайн
- Material 3: NavigationRail слева (Hosts, Snippets, Settings), вкладки сверху, скругления, мягкие переходы, side sheet для редактирования.
- Схема: тёмная / светлая / как в системе. Плотность: compact / comfortable.
- Палитра команд `Ctrl+K`: подключиться, новая вкладка, сменить тему, настройки.
- Вдохновение: Material 3, keqdroid.

### 4.2 Источники цвета (`ThemeService`)
Все приводятся к одному виду - seed-цвет или готовые M3-токены → `ColorScheme` для UI + палитра терминала. Смена применяется на лету.

1. **Встроенные пресеты** - M3 baseline, Catppuccin, Gruvbox, Tokyo Night, Nord.
2. **Системный акцент**
   - Linux: `xdg-desktop-portal` → `org.freedesktop.appearance` (`color-scheme`, `accent-color`), подписка на изменения по D-Bus.
   - Windows: цвет акцента и тёмный режим системы, подложка Mica (Win11).
3. **Файлы дотов** - главное для «меняется под обои». Слежение за файлом, перечитывание без перезапуска:
   - свой формат `~/.config/vysh/colors.json` (M3-токены) + **готовые шаблоны для matugen и wallust** в `themes/templates/` - любой сетап, генерирующий цвета из обоев, просто подключает наш шаблон;
   - pywal: `~/.cache/wal/colors.json`;
   - caelestia: адаптер под её файл схемы (путь уточняется при реализации);
   - GTK-тема как последний фолбэк.
4. **Палитра терминала** отдельно: из темы приложения / из дотов / пресет / импорт (Alacritty, kitty, foot, iTerm).

### 4.3 Настройки
- **Внешний вид** - тема, источник цвета, схема, прозрачность, плотность
- **Терминал** - шрифт, размер, лигатуры, курсор, scrollback, звонок, копирование при выделении
- **Окно** - режим декораций (см. 5)
- **Подключения** - keepalive, таймауты, автопереподключение, known_hosts
- **SFTP** - параллельность, папка загрузок по умолчанию, поведение при конфликте имён
- **Безопасность** - keyring / vault, автоблокировка
- **Горячие клавиши** - переназначение
- **Данные** - импорт `ssh_config`, экспорт/импорт, портативный режим

## 5. Окно и оконные менеджеры

Принцип: **обычное окно, никаких хаков.**
- `app_id` / `WM_CLASS` = `vysh` → работают правила Hyprland/sway/i3 (`windowrule = ..., class:vysh`).
- Нет фиксированных размеров и самовольного позиционирования, разумный минимальный размер, без «поверх всех».
- **Декорации: `auto | system | custom`**
  - `system` - рамку рисует WM (на тайлинге её просто нет), вкладки в контенте;
  - `custom` - свой заголовок с вкладками внутри (как Termius/браузеры), на Windows со snap layouts;
  - `auto` - `custom` на Windows, GNOME, KDE; без своей рамки, если `XDG_CURRENT_DESKTOP` - Hyprland, sway, i3, niri, river и т.п.
- Wayland нативно, X11 - фолбэк. HiDPI и дробное масштабирование.
- Прозрачность - опционально (для блюра Hyprland/KDE). Трей - опционально, выключен по умолчанию.

### Горячие клавиши
Всё с Shift, чтобы не отнимать `Ctrl+W`, `Ctrl+R` и т.п. у shell. Всё переназначается.

| Действие | Клавиши |
|---|---|
| Новая вкладка (палитра хостов) | `Ctrl+Shift+T` |
| Закрыть вкладку | `Ctrl+Shift+W` |
| Следующая / предыдущая | `Ctrl+Tab` / `Ctrl+Shift+Tab` |
| Вкладка по номеру | `Alt+1..9` |
| Палитра команд | `Ctrl+K` |
| Копировать / вставить | `Ctrl+Shift+C` / `Ctrl+Shift+V` |
| Поиск в терминале | `Ctrl+Shift+F` |
| Переподключить | `Ctrl+Shift+R` |
| SFTP-панель | `Ctrl+Shift+E` |
| Настройки | `Ctrl+,` |

## 6. Разработка, сборка, релизы

### 6.1 Разработка
- Windows: Flutter SDK + VS Code (расширение Flutter) + Visual Studio 2022 с «Desktop development with C++». `flutter run -d windows`.
- Linux (Arch): Flutter из AUR или `fvm`. `flutter run -d linux`. С Windows Linux-версию можно гонять через WSL2 (WSLg); поведение в Hyprland и других WM проверяется на живом Linux.
- Версия Flutter закреплена (`fvm` / `.fvmrc`), чтобы сборки были одинаковыми везде.

### 6.2 CI (GitHub Actions, бесплатно для публичного репозитория)
- **На каждый push / PR:** `flutter analyze` + тесты на Linux (~1-2 мин).
- **На тег `v*`:** параллельно
  - Linux - в Docker на старой базе (минимальную glibc подбираем под текущий Flutter, цель - Astra): **AppImage, .deb, tar.gz**;
  - Windows - **zip «распаковал и запустил»** (позже - установщик Inno Setup);
  - всё прикрепляется к GitHub Release.
- Упаковка - **fastforge** (бывший flutter_distributor), один конфиг на все форматы.
- Версия в `pubspec.yaml` должна совпадать с тегом (CI проверяет).

### 6.3 Дистрибуция
- Linux: AppImage (основной, «запустить где угодно»), .deb (Astra/Debian/Ubuntu), AUR `vysh-bin` (обновляется из CI), tar.gz.
- Windows: zip (данные в `%APPDATA%\vysh`), позже установщик.
- Flatpak - позже и под вопросом: песочница мешает читать `~/.ssh` и файлы дотов.
- Проверка обновлений в приложении через GitHub Releases API (только уведомление).
- Ограничения: Windows без подписи → предупреждение SmartScreen при первом запуске; Astra в режиме замкнутой среды требует подписанных бинарников.

## 9. Аналоги и чем vysh отличается

| Аналог | Стек | Почему не он |
|---|---|---|
| Tabby | Electron | Тяжёлый, свой стиль, нет цветов из дотов, Electron на Astra рискован |
| Voltius | Tauri + React + xterm.js + russh | Ближайший по духу, но WebKitGTK на старых дистрах, AGPL, Pro-тариф, перегружен |
| Electerm | Electron | Комбайн всех протоколов, перегруженный интерфейс |
| sshPilot | Python + GTK4/libadwaita | Нет Windows, нужны свежие дистрибутивы |
| WindTerm | C++/Qt | Последний релиз в 2025, исходники открыты не полностью, старомодный UI |
| XPipe | Java | Хаб, а не терминал; часть функций платная |
| ServerBox | Flutter | Тот же стек, но это мониторинг серверов для телефона - используем как референс кода |
| MobaXterm, Xshell, SecureCRT | проприетарные | Закрытые, Windows-центричные, частично платные |

**Ниша vysh:** минимализм + Material You + цвета из дотов на лету + корректное поведение в тайлинговых WM + Windows + старые дистрибутивы. Одновременно этого нет ни у кого.
