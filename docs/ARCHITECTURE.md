# vysh - концепция и архитектура

> Статус: версия 2 (2026-10-16, vysh 0.5.4). Документ - источник правды для решений; меняем его вместе с кодом. Актуальный список возможностей - README.
>
> **Что из этого ещё не сделано:** `TerminalEngine` (терминал - напрямую xterm2, своя копия в `third_party/xterm2`), vault-файл с мастер-паролем, ssh-agent/Pageant (режим `agent` пока берёт незашифрованные ключи из `~/.ssh`), импорт `~/.ssh/config`, докачка SFTP, палитра команд `Ctrl+K`, поиск в терминале, AppImage / .deb / AUR / установщик Windows.

## Надёжность: принятые правила

- **Файлы конфигурации** (`JsonStore`) пишутся через временный файл и атомарный `rename` поверх старого; прежняя версия остаётся в `.bak`, битый файл перед перезаписью откладывается в `.corrupt-<время>`. Ошибка записи показывается пользователю.
- **Один экземпляр на профиль.** Пока vysh запущен, он держит блокировку `vysh.lock`; второй запуск с тем же профилем только сообщает об этом и ничего не пишет.
- **Загрузка по SFTP** идёт во временный `.имя.vysh-*.part` рядом с целью и заменяет файл только после успеха (posix-rename, либо старый файл отодвигается и возвращается при сбое). Симлинки не заменяются.
- **Скачивание** идёт в `имя.vysh-part`, путь резервируется на время передачи; имена с сервера очищаются (`LocalFiles.safeName`) и не могут выйти за папку загрузки.
- **Сессия** нумерует попытки подключения: всё, что пришло от прежней попытки (поздний shell, `done` старого транспорта, SFTP-канал), освобождается и не трогает новую. Закрытие вкладки прерывает попытку сразу.
- **Пароль в памяти** сессии привязан к цели `user@host:port` и способу входа; смена цели его сбрасывает. Сохранённый пароль при смене адреса, порта или пользователя в редакторе удаляется, а не уходит на новый сервер.
- **Системные программы** запускаются без разбора строки shell'ом (на Windows не через `cmd`). Файлы с сервера, которые Windows запустила бы (`.bat`, `.exe`, `.ps1` и т.п.), открываются в Блокноте.

## 0. Что это

**vysh** - SSH-менеджер подключений «как Termius, но без платного и лишнего».

Принципы:
- **Минимум функций, максимум удобства.** Только то, что нужно для ежедневной работы с серверами.
- **Красиво.** Material 3 / Material You, плавные анимации, темы.
- **Везде одинаково хорошо.** Windows 10/11, любой Linux - от Arch с Hyprland до Astra, macOS 12+ и Android 8+.
- **Уважает систему.** Окно ведёт себя как обычное приложение в любом оконном менеджере; цвета подхватываются из системных дотов и меняются вместе с обоями.
- **Локально и бесплатно.** Без аккаунтов, облака, подписок и телеметрии. Лицензия GPL-3.0-or-later.

## 1. Функциональность

### 1.1 MVP
| Блок | Что входит |
|---|---|
| **Главная (Hosts)** | Карточки хостов: имя, `user@host:port`, группы, цветные метки, поиск, индикатор доступности (TCP-ping), массовые действия |
| **Редактор хоста** | Боковая панель (side sheet): адрес, порт, логин, пароль / ключ / агент, группа, цвет, KeepAlive. Кнопка «Подключиться без сохранения». Команда при старте - позже |
| **Быстрое подключение** | `user@host:port` в поле поиска и Enter (позже и в палитре команд) |
| **Вкладки** | Каждая сессия - вкладка; Hosts - закреплённая первая. Перетаскивание, дублирование, переподключение, индикатор состояния |
| **Терминал** | 256 цветов / truecolor, мышь, выделение и копирование, scrollback, нагрузка сервера в строке состояния; локальная сессия без SSH. Шрифт: системный моноширинный или свой файл, межстрочный интервал (см. 4.4). Поиск по буферу - позже |
| **SFTP** | Панель файлов у вкладки (локально ⇄ сервер), drag&drop из проводника/файлового менеджера, очередь передач с прогрессом/скоростью/отменой, mkdir / rename / delete / chmod, «открыть в локальном редакторе → залить при сохранении». Докачка - позже |
| **Диагностика** | Экран ошибки с причиной и журналом, ping, трассировка, проверка порта |
| **Безопасность** | Проверка ключа сервера (known_hosts, диалог при первом подключении и при смене ключа), пароли только в защищённом хранилище, защита вставки нескольких строк |
| **Настройки и темы** | См. раздел 4 |
| **Импорт** | Из `~/.ssh/config` - ещё не сделан |

### 1.2 Потом (по приоритету)
1. Сниппеты - сохранённые команды, отправка во вкладку
2. Проброс портов (L / R / SOCKS)
3. Jump host / ProxyJump
4. Split-панели внутри вкладки
5. Синхронизация без своего облака - экспорт/импорт зашифрованного файла (Syncthing, git, Nextcloud)
6. Broadcast ввода в несколько вкладок
7. SFTP «следует за текущей папкой терминала» (OSC 7)
8. Режим хоста «через системный ssh» - для Kerberos, FIDO2, ProxyCommand

### 1.3 Не делаем
Аккаунты, своё облако, командная работа, подписки, телеметрия, «комбайн всех протоколов» (RDP, VNC, Telnet и т.п.).

## 2. Стек

| Слой | Выбор | Почему |
|---|---|---|
| UI | **Flutter** (Dart), Material 3 | Material You из коробки, один код на Windows, Linux, macOS и Android, Wayland через GTK |
| Состояние | **Riverpod** | Простое DI и реактивность без магии |
| SSH + SFTP | **`dartssh2`** | Чистый Dart, живой (4.1.x, 2026), есть SFTP, проброс портов, ed25519/RSA/ECDSA, ChaCha20/AES-GCM. Без нативной сборки |
| Терминал | **`xterm2`** | Поддерживаемый форк `xterm.dart`. Своя копия с правками в `third_party/xterm2` (клавиатура Android не в анонимном режиме) |
| Окно | `window_manager`, `screen_retriever` | Управление декорациями, размером, положением |
| Секреты | `flutter_secure_storage` | DPAPI на Windows, Secret Service на Linux, Keychain на macOS, Android Keystore. Vault-файл - позже, см. 3.5 |
| Файлы | `file_selector`, `desktop_drop`, `path_provider` | Диалоги выбора, файлы из ОС в окно, системные папки |
| Отрисовка | Skia по умолчанию | Impeller держит заметно больше памяти; переключается в настройках, применяется после перезапуска |

Версия Flutter закреплена в workflow CI (сейчас 3.47.6).

**Почему не Rust.** Огромные файлы и особое шифрование не нужны, поэтому скорость нативного ядра не окупает усложнения сборки. Прецедент: ServerBox (Flutter + dartssh2 + xterm, вкладки и SFTP на Linux/Windows).

**Запасной план.** SSH спрятан за портами `SshTransport` и `SftpClient`. Если `dartssh2` не справится, его можно заменить на `russh`, UI при этом не трогаем. Терминал пока без своего порта: если `xterm2` не справится, сначала выделяем `TerminalEngine`, потом меняем движок (например, `flutter_alacritty`).

### Отвергнутые варианты
- **Tauri + xterm.js** - WebKitGTK на старых дистрибутивах (Astra) болезненный.
- **Qt/QML** - Material 3 рисовать руками, терминальный виджет под Windows сложно.
- **Electron** - тяжёлый, на Astra риск.
- **Системный OpenSSH как основа** - пароли, ключи сервера и состояние пришлось бы выковыривать из текста.

## 3. Архитектура

```
┌──────────────────────────── ui (Flutter, M3) ─────────────────────────────┐
│ AppShell · TabStrip (в заголовке или под ним) · HomeSwitcher              │
│ HostsPage · HostEditor · SessionView · SftpPane · SettingsPage            │
└───────────────▲───────────────────────────────────────────────────────────┘
                │ Riverpod providers
┌───────────────┴──────────────────── app ─────────────────────────────────┐
│ HostsController  TabsController  SettingsController  TransferQueue       │
│ ExternalColors   UserFonts       TerminalSession     SftpActions         │
└───────────────▲───────────────────────────────────────────────────────────┘
                │
┌───────────────┴──────────────────── domain ──────────────────────────────┐
│ Модели: Host, SessionTab, ExternalColors, Catppuccin                     │
│ Сервисы: known_hosts, нагрузка сервера, разбор шрифтов                   │
│ Порты: SshTransport · SftpClient · TerminalShell · LocalShellLauncher · …│
└───────────────▲───────────────────────────────────────────────────────────┘
                │ реализации
┌───────────────┴─────────────────── infra ────────────────────────────────┐
│ ssh/       dartssh2 → SshTransport, SftpClient                           │
│ local/     Process → TerminalShell (PTY: script, flutter_pty)            │
│ secrets/   KeyringSecretStore                                            │
│ storage/   JSON-файлы в папке профиля, AppPaths                          │
│ platform/  окно, источники цветов, шрифты, локальные файлы, сеть         │
└───────────────────────────────────────────────────────────────────────────┘
```

Правило зависимостей: **ui → app → domain ← infra.** Domain знает только `dart:` и сам себя: ни Flutter-виджетов, ни Riverpod, ни библиотек. `test/architecture_test.dart` проверяет это на каждом прогоне тестов.

### 3.1 Сущности
- **Host** - id, label, address, port, username, auth (password | key | agent), keyPath, group, color, keepAliveSeconds, lastConnectedAt. Секретов нет, пароль лежит в SecretStore по id хоста.
- **Group** - имя группы у хоста (один уровень).
- **Session** - живое соединение: Host + SshTransport или LocalShellLauncher + состояние (`connecting / ready / lost / closed`) + keepalive. Локальная сессия не использует SSH и SFTP; `Host` нужен только для заголовка вкладки.
- **Tab** - UI-обёртка над Session: терминал + опциональная SFTP-панель (позже - дерево split-панелей).
- **Transfer** - задача SFTP: направление, пути, размер, прогресс, скорость, статус.
- **Theme** - seed-цвет или готовые M3-роли + 16-цветная палитра терминала + источник.

### 3.2 Жизненный цикл подключения
1. Клик по карточке → новая вкладка в `connecting`.
2. Проверка ключа сервера: новый → диалог «доверять?»; изменился → предупреждение.
3. Аутентификация: пароль из SecretStore / ключ / агент. Ошибка → диалог ввода с галкой «сохранить». Одноразовые коды (OTP, PIN) всегда спрашиваются у человека.
4. PTY `xterm-256color`, размер следует за размером вкладки → `ready`.
5. Локальная сессия запускает оболочку текущей системы; для PTY на Unix используется `script`, на Android - `flutter_pty`, на Windows - pipes без PTY.
6. Обрыв → `lost`, экран ошибки с журналом, «Переподключить» (Enter).
7. SFTP открывается по требованию поверх **того же** соединения (отдельный канал), повторный логин не нужен.

### 3.3 SFTP
- `TransferQueue`: параллельно несколько передач, остальные ждут; история ограничена 200 записями.
- Конфликт имён при загрузке: заменить / пропустить / отменить.
- «Открыть локально»: скачиваем во временную папку, открываем системным редактором, следим за изменением → заливаем обратно. Загрузки одного файла идут по очереди, последняя версия заливается всегда.
- Докачка по смещению - позже.

### 3.4 Хранение
- Windows: `%APPDATA%\vysh\`; Linux: `$XDG_CONFIG_HOME/vysh/` (обычно `~/.config/vysh/`); macOS: `~/Library/Application Support/vysh/`; Android: внутреннее хранилище приложения. `VYSH_CONFIG_DIR` задаёт свою папку (ПК).
- Файлы: `hosts.json`, `settings.json`, `known_hosts.json`, `colors.json` (свои цвета, если есть), `fonts/` (добавленные шрифты), `vysh.lock`.
- Человекочитаемо и **без секретов** - можно класть в git или Syncthing.
- Данные всегда в профиле пользователя, независимо от того, откуда запущен exe: обновление = удалить старую папку и распаковать новую.

### 3.5 Секреты
- Сейчас - системное хранилище: DPAPI на Windows, Secret Service на Linux, Keychain на macOS, Android Keystore. Если его нет, vysh пишет об этом и спрашивает пароль при каждом подключении.
- Позже, для систем без хранилища (голый Hyprland без keyring, закрытая Astra) - **vault-файл** с мастер-паролем (Argon2id → XChaCha20-Poly1305), разблокировка при старте, автоблокировка по таймеру.
- Ключи: ссылкой на файл в `~/.ssh`. Позже - ssh-agent (OpenSSH agent, Pageant).

## 4. Внешний вид и темы

### 4.1 Дизайн
- Material 3: вкладки сверху, на главной вкладки «Хосты» и «Настройки», скругления, мягкие переходы, side sheet для редактирования.
- Схема: тёмная / светлая / как в системе. Плотность: обычная / компактная.
- Палитра команд `Ctrl+K` (подключиться, новая вкладка, сменить тему, настройки) - позже.
- Интерфейс для тех, кто знает, что делает: без пояснений под настройками и без подставленных значений.
- Вдохновение: Material 3, keqdroid.

### 4.2 Источники цвета
Все приводятся к одному виду - seed-цвет или готовые M3-токены → `ColorScheme` для UI + палитра терминала. Смена применяется на лету. Подробно - [THEMES.md](THEMES.md).

1. **Свои** - 9 акцентов (на Android вместо них Monet).
2. **Catppuccin** - Latte, Frappé, Macchiato, Mocha и 14 акцентов.
3. **Системный акцент**
   - Linux: `xdg-desktop-portal` → `org.freedesktop.appearance` (`color-scheme`, `accent-color`), подписка на изменения по D-Bus.
   - Windows: цвет акцента и тёмный режим системы.
   - Android: Monet (Material You), значок приложения в тех же цветах.
4. **Файлы дотов** (Linux) - главное для «меняется под обои». Слежение за файлом, перечитывание без перезапуска:
   - свой `colors.json` в профиле + **готовые шаблоны для matugen и wallust** в `themes/templates/`;
   - pywal: `~/.cache/wal/colors.json`;
   - caelestia: `~/.local/state/caelestia/scheme.json`.
5. **Палитра терминала** следует акценту приложения, а с цветами из дотов берёт их 16 цветов.

### 4.3 Настройки
- **Внешний вид** - тема, источник цвета, заголовок окна, язык, компактный интерфейс
- **Хосты** - проверка доступности, KeepAlive
- **Терминал** - шрифт, размер, межстрочный интервал, запоминание размера, буфер обмена (копирование при выделении, вставка средней кнопкой и правым кликом, подтверждение многострочной вставки), панель клавиш (Android)
- **Производительность** - история терминала, частота проверок, движок отрисовки
- **Данные** - папка загрузок, папка профиля
- Позже: горячие клавиши (переназначение), безопасность (vault), импорт `ssh_config`

### 4.4 Шрифты терминала
Ничего тяжёлого в сборку не кладём. Три источника:

1. **Установленные в системе.** Список только моноширинных: vysh сам читает шрифты из системных папок (на Linux - список fontconfig, `fc-list`) и разбирает заголовки TTF / OTF / TTC (`domain/services/font_info.dart`). Моноширинность меряется по ширине латинских букв и цифр через `cmap` и `hmtx`: так в списке оказываются и CJK-шрифты с полуширинной латиницей, и Nerd Font без Mono в имени, а символьные шрифты и эмодзи - нет. Системный шрифт Flutter берёт по имени семейства. Разбор идёт в отдельном изоляте, когда открыты настройки.
2. **Свой файл.** «Добавить шрифт…» → `.ttf` / `.otf` до 32 МБ копируется в `fonts/` профиля и регистрируется через `FontLoader` под своим именем (`vysh-file:<файл>`), чтобы не спутаться с системным. Выбранный файл загружается до первого кадра. Немоноширинный шрифт добавляется с предупреждением. Если в файле только обычное начертание, жирное Flutter рисует сам. Работает везде, включая Android.
3. **По умолчанию.** Windows и Linux: Cascadia Mono и запасная цепочка (JetBrains Mono, Consolas, DejaVu Sans Mono…). macOS и Android: **JetBrains Mono NL** из сборки (Regular + Bold, около 420 КБ, OFL): своих хороших моноширинных там нет. Flutter не умеет класть ассеты только в часть платформ, поэтому файлы есть во всех сборках, но на Windows и Linux шрифт только в запасной цепочке.

Запасная цепочка остаётся при любом выборе: символы, которых нет в шрифте (кириллица, рамки, значки Nerd Font, эмодзи), берутся из неё. Nerd Font в сборку не кладём - в настройках ссылка на nerdfonts.com. Межстрочный интервал 1.0-1.6, лигатуры выключены всегда.

## 5. Окно и оконные менеджеры

Принцип: **обычное окно, никаких хаков.**
- `app_id` / `WM_CLASS` = `vysh` → работают правила Hyprland/sway/i3 (`windowrule = ..., class:vysh`).
- Нет фиксированных размеров и самовольного позиционирования, разумный минимальный размер, без «поверх всех». Размер и положение окна восстанавливаются (в Wayland положение решает композитор).
- **Заголовок: `auto | system | custom`** (в настройках два варианта, `auto` - по умолчанию)
  - `system` - рамку рисует WM (на тайлинге её просто нет), вкладки в контенте;
  - `custom` - свой заголовок с вкладками внутри (как Termius/браузеры), на Windows со snap layouts, на macOS рядом с нативным светофором;
  - `auto` - `custom` на Windows, macOS, GNOME, KDE; системный, если `XDG_CURRENT_DESKTOP` - Hyprland, sway, i3, niri, river и т.п.
- Wayland нативно, X11 - фолбэк. HiDPI и дробное масштабирование.

### Горячие клавиши
Всё с Shift, чтобы не отнимать `Ctrl+W`, `Ctrl+R` и т.п. у shell. На macOS - привычные ⌘-сочетания.

| Действие | Клавиши | macOS |
|---|---|---|
| Новая вкладка / быстрое подключение | `Ctrl+Shift+T` | `⌘T` |
| Закрыть вкладку | `Ctrl+Shift+W` | `⌘W` |
| Следующая / предыдущая | `Ctrl+Tab` / `Ctrl+Shift+Tab` | то же |
| Вкладка по номеру (1 = главная) | `Alt+1..9` | `⌘1..9` |
| Новый хост | `Ctrl+Shift+N` | `⌘N` |
| Переподключить | `Ctrl+Shift+R` | `⌘R` |
| SFTP-панель | `Ctrl+Shift+E` | `⌘E` |
| Копировать / вставить | `Ctrl+Shift+C` / `Ctrl+Shift+V` | `⌘C` / `⌘V` |
| Настройки | `Ctrl+,` | `⌘,` |

Позже: палитра команд `Ctrl+K`, поиск в терминале `Ctrl+Shift+F`, переназначение сочетаний.

## 6. Разработка, сборка, релизы

### 6.1 Разработка
- Windows: Flutter SDK + VS Code (расширение Flutter) + Visual Studio 2022 с «Desktop development with C++» и «C++ ATL». `flutter run -d windows`, релизный zip - `tools\build-windows.ps1`.
- Linux (Arch): Flutter из AUR или `fvm`, пакеты `ninja-build libgtk-3-dev libsecret-1-dev`. `flutter run -d linux`. Поведение в Hyprland и других WM проверяется на живом Linux.
- macOS: полный Xcode. `flutter run -d macos`, DMG - `tools/build_dmg.sh`.
- Android: Android SDK. `tools/build_local.sh apk`.
- Демо-стенд: пять SSH-серверов в Docker и отдельный профиль (`tools/demo`).

### 6.2 CI (GitHub Actions, публичный репозиторий)
- **На каждый push / PR:** `flutter analyze` + тесты + проверка патча xterm2 на Linux.
- **На тег `v*`:** проверка, что версия тега = `pubspec.yaml` = `lib/app/version.dart` и есть запись в CHANGELOG, затем параллельно:
  - Linux (ubuntu-22.04, glibc 2.35) - **tar.gz** и **PKGBUILD** для Arch;
  - Windows - **zip «распаковал и запустил»**;
  - macOS - **DMG** (универсальная сборка, без подписи Apple);
  - Android - **APK** под `arm64-v8a`, `armeabi-v7a`, `x86_64`, подписанные v1 + v2 + v3 (если в секретах есть ключ);
  - текст релиза из CHANGELOG, всё прикрепляется к GitHub Release.
- Порядок выпуска - [RELEASING.md](RELEASING.md).

### 6.3 Дистрибуция
- Сейчас: Windows zip, Linux tar.gz, PKGBUILD (Arch), macOS DMG, Android APK.
- Позже: AppImage на старой glibc (Astra), .deb, AUR `vysh-bin` из CI, установщик Windows (Inno Setup).
- Flatpak - под вопросом: песочница мешает читать `~/.ssh` и файлы дотов.
- Ограничения: Windows без подписи → предупреждение SmartScreen при первом запуске; macOS без нотаризации → «Всё равно открыть»; Astra в режиме замкнутой среды требует подписанных бинарников.

## 7. Структура репозитория

Направление зависимостей: **ui → app → domain ← infra**.

```
vysh/
  lib/
    main.dart             # запуск: папка профиля, блокировка, окно, свой шрифт, ProviderScope
    domain/               # только dart: - без Flutter-виджетов, Riverpod и библиотек
      models/             # Host, SessionTab, ExternalColors, Catppuccin, ошибки локальных файлов
      ports/              # SSH/SFTP, TerminalShell, LocalShellLauncher, SecretStore, DocumentStore
      services/           # known_hosts, нагрузка сервера, разбор шрифтов
    app/                  # связывание и логика приложения (Riverpod), без виджетов
      dependencies.dart   # порты → реализации из infra (тесты переопределяют)
      controllers/        # хосты, настройки, вкладки, очередь передач, цвета, шрифты
      terminal/           # сессия (SSH + xterm2), вход на сервер, ввод с клавиатуры
      sftp/               # действия с файлами, содержимое папки, локальное редактирование
      settings/           # AppSettings, заголовок окна, шрифт терминала
    l10n/                 # все строки RU/EN; ошибки приходят кодами и собираются здесь
    infra/                # реализации портов: dartssh2, локальная оболочка, keyring, JSON-файлы, платформа
    ui/                   # экраны и виджеты
  test/                   # регрессии ревью, слои, локализация, контроллеры, шрифты
  assets/                 # значки, шрифт JetBrains Mono NL (fonts/, OFL)
  third_party/xterm2/     # xterm2 5.2.0 + vysh.patch (tools/xterm2/verify.sh)
  linux/ windows/ android/ macos/
  themes/templates/       # шаблоны для matugen / wallust
  packaging/arch/         # PKGBUILD
  tools/                  # сборка, релиз, демо-стенд, проверка xterm2
  .github/workflows/      # CI и релизы
  docs/
```

## 9. Аналоги и чем vysh отличается

| Аналог | Стек | Почему не он |
|---|---|---|
| Tabby | Electron | Тяжёлый, свой стиль, нет цветов из дотов, Electron на Astra рискован |
| Voltius | Tauri + React + xterm.js + russh | Ближайший по духу, но WebKitGTK на старых дистрах, AGPL, Pro-тариф, перегружен |
| Electerm | Electron | Комбайн всех протоколов, перегруженный интерфейс |
| sshPilot | Python + GTK4/libadwaita | Нет Windows, нужны свежие дистрибутивы |
| WindTerm | C++/Qt | Последний релиз в 2025, исходники открыты не полностью, старомодный UI |
| XPipe | Java | Хаб, а не терминал; часть функций платная |
| ServerBox | Flutter | Тот же стек, но это мониторинг серверов для телефона - используем как референс кода |
| MobaXterm, Xshell, SecureCRT | проприетарные | Закрытые, Windows-центричные, частично платные |

**Ниша vysh:** минимализм + Material You + цвета из дотов на лету + корректное поведение в тайлинговых WM + Windows, macOS и Android + старые дистрибутивы. Одновременно этого нет ни у кого.
